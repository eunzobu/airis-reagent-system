# AIRIS

멀티센서 데이터를 활용한 비파괴 시약 검사 및 보관 시스템입니다. 시약 분류와 잔량 추정에 필요한 데이터를 수집하고, 서버의 판정 결과를 UI로 전달합니다.

**핵심 기여:** 센서 원시값부터 서버 저장값까지 비교해 정전용량 측정 포화의 발생 구간을 좁혔습니다. CAPDAC 조정 로직과 이동평균을 적용하고 측정 조건을 바꿔 재확인했습니다.

## 데이터 흐름

```text
정전용량 / NIR / 온습도 센서
          ↓
ESP32 / Raspberry Pi
          ↓
Node-RED → InfluxDB 시계열 데이터 저장
                   ↓
           FastAPI 기반 AI 서버
                   ↓
                React UI
```

각 측정값에 슬롯 정보, 센서 종류, 측정 시간을 부여해 검사 대상을 구분했습니다. NIR 데이터는 LED 점등 직후의 불안정한 구간을 제외하고 수집했습니다.

## 시약 판정 방식

1. 정전용량, NIR, 온습도 데이터의 누락값을 처리하고 정규화합니다.
2. 평균, 범위, 기울기, 변화량, 포화 비율 등의 특징을 추출해 입력 벡터를 구성합니다.
3. MLP 기반 분류로 산성, 중성, 염기성을 구분하고 세부 시약을 분류합니다.
4. 정전용량과 광학 특징을 이용한 회귀로 잔량을 추정합니다.
5. 신뢰도가 낮은 판정에는 동일 슬롯의 과거 데이터와 비교하는 kNN 보정 방식을 적용합니다.

## 문제 해결: 정전용량 측정 포화

**증상:** 특정 측정 조건에서 센서 값이 불안정해지고 포화되는 현상이 반복됐습니다.

**원인 추적:** 센서 원시값, 장치 전송값, 서버 저장값을 순서대로 비교했습니다. 통신과 저장 과정에서 값이 바뀌지 않는 것을 확인한 뒤 센서 측정 범위와 CAPDAC 설정을 점검했습니다.

**조치:** 측정값에 따라 CAPDAC 설정을 자동 조정하도록 수정했습니다. 순간적인 노이즈의 영향을 줄이기 위해 이동평균을 적용했습니다.

**확인 결과:** 시약과 측정 조건을 바꿔 반복 측정하며 안정화 여부를 확인했습니다.

## 역할과 기술

| 구분 | 내용 |
| --- | --- |
| 본인 문제 해결 | 데이터 경로별 값 비교, 측정 범위 점검, CAPDAC 조정과 이동평균 적용, 조건 변경 후 재확인 |
| 시스템 기술 | ESP32와 Raspberry Pi의 데이터 수집, Node-RED 연동, FastAPI 판정 API, React 결과 화면 |
| 모델 구성 | MLP 기반 분류와 회귀, kNN 보정 |

## 제어와 데이터 관리

시약 적재 후 슬롯 ID와 OCR 결과로 대상을 식별하고, 멀티센서 측정과 AI 판정을 거쳐 결과를 저장합니다. React 화면에서 시약과 검사 결과를 확인합니다.

Node-RED는 브라우저와 장치의 HTTP 요청을 각 제어 흐름으로 전달합니다. 측정 상태를 관리해 중복 명령을 막고, 측정 완료 여부를 판단합니다. `scan_id`를 기준으로 데이터를 조회하고 예측 결과를 UI용 JSON으로 반환합니다.

InfluxDB에는 측정 시간, 장치 ID, 센서 ID와 측정값을 저장합니다. 시계열 데이터의 조건별 조회와 Node-RED 연동을 고려해 사용했습니다.
